# Установщик GLPI Agent по SSH

## Назначение и пользователь

Локальное приложение с окном для администратора, который устанавливает GLPI Agent на удалённое устройство по SSH. Цель — ввести адрес устройства и учётные данные, автоматически выбрать установщик для Astra Linux либо Linux Mint и увидеть результат.

## Основной сценарий

1. Администратор запускает приложение на своём компьютере.
2. Вводит IP-адрес устройства, SSH-логин, пароль и URL сервера GLPI. URL можно изменить при каждом запуске; локальный `.env` может предложить значение по умолчанию.
3. Приложение подключается по SSH, подтверждает ключ ранее неизвестного узла и читает `/etc/os-release`.
4. Для Astra Linux загружает архив, конфигурацию и скрипт из `linux_astra`; для Linux Mint — AppImage и скрипт из `linux_mint`.
5. Запускает установку с правами администратора и показывает ход и итог. Пароль используется только для SSH и `sudo` во время запуска.

## Первая версия

- Один узел за запуск; SSH с паролем, стандартный порт 22.
- Только Astra Linux и Linux Mint, без догадки для неподдерживаемых систем.
- Упакованные в репозиторий GLPI Agent 1.16 и имеющиеся скрипты установки.
- Локальный `.env` для URL по умолчанию. `.env` исключён из Git; целевой IP и пароль не сохраняются.
- Ошибки подключения, аутентификации, определения ОС и удалённой команды отображаются пользователю.

## Вне первой версии

Массовая установка, SSH-ключи, выбор SSH-порта, централизованное хранение учётных данных, автоматическое обновление агента и поддержка других ОС.

## Данные и безопасность

- В исходниках, документации и тестах нет реальных адресов инфраструктуры. Старый адрес сервера GLPI находится только в локальном `.env`.
- Пароль отображается маской, не записывается в файлы и логи. URL сервера валидируется перед удалённым вызовом.
- Ключ известного SSH-узла проверяется; для неизвестного узла пользователь видит отпечаток и явно подтверждает соединение. Ключ не сохраняется автоматически.
- Для установки нужны доступный SSH, пароль учётной записи и право запускать `sudo` с этим паролем либо вход под `root`.

## Платформа и допущения

- Окно запускается на компьютере администратора с Python 3.10+ и графическим окружением. Для SSH используется Paramiko.
- Устройства доступны по сети, на них есть `bash`, `sudo` и `apt`. Зависимости пакетов устанавливаются имеющимися скриптами через сеть.
- Адрес GLPI может быть HTTP или HTTPS; приложение не меняет сервер GLPI.
- Значение в `.env` служит подсказкой в поле, а не скрытой настройкой установки: администратор видит его перед запуском.

## Критерии приёмки

| ID | Наблюдаемое поведение |
| --- | --- |
| AC-01 | Окно принимает IP, SSH-логин и пароль; пароль скрыт. |
| AC-02 | Пользователь вводит или меняет URL GLPI при каждом запуске; локальный `.env` не отслеживается Git. |
| AC-03 | По `/etc/os-release` выбирается Astra или Mint, остальные системы останавливаются с понятной ошибкой. |
| AC-04 | Для Astra и Mint передаются нужные локальные файлы и выполняется соответствующий скрипт с указанным URL GLPI. |
| AC-05 | Успех и сбой SSH/установки показываются без вывода пароля. |
| AC-06 | В отслеживаемых файлах отсутствует прежний адрес GLPI. |
| AC-07 | На Windows можно запустить переносимую сборку без установленного Python; в ней есть пакеты для Astra и Mint. |
| AC-08 | Быстрый вывод установки не блокирует окно: показываются этапы, ошибки и краткий счётчик скрытых подробных строк. |
| AC-09 | Локальный `.env` не попадает в переносимую сборку; при необходимости его можно положить рядом с `.exe`. |
