# Работа с шаблоном в Codex CLI

## Новый продукт

Создайте отдельный репозиторий по README и запустите `codex` из его корня. Codex читает применимые AGENTS.md; PLANS.md подключается правилом из AGENTS.md. Проверьте разрешения CLI перед выполнением команд, особенно вне репозитория.

Запрос:

> Прочитай AGENTS.md и PLANS.md. Создаём [продукт] для [пользователей]. Основные сценарии: […]. Ограничения: […]. Исследуй репозиторий, задай блокирующие вопросы, сохрани docs/SPEC.md и docs/plans/initial.md. Затем выполняй этапы в пределах этой задачи, проверяя критерии и обновляя план.

Стек выбирается после изучения задачи. Не устанавливайте зависимости шаблона: их здесь нет. Команды запуска, тестирования и сборки появятся после выбора и настройки стека конкретного продукта.

## Реализация функции

> Прочитай AGENTS.md, PLANS.md, docs/SPEC.md и актуальный план. Нужно [поведение и ограничения]. Обнови требования и создай docs/plans/<имя>.md. Реализуй задачу, проверь критерии приёмки и обнови состояние. Для логики сначала покажи ожидаемое падение теста по нужной причине.

Для мелкой правки:

> Исправь [проблема]. Изучи применимые инструкции, внеси минимальное изменение и выполни подходящую проверку. Большой план не нужен.

## Продолжение после перерыва

Запустите `codex` в корне того же проекта. Новый чат допустим: состояние должно быть в файлах.

> Прочитай AGENTS.md, PLANS.md, docs/SPEC.md и docs/plans/<имя>.md. Сверь точку продолжения с текущим кодом и состоянием Git. Продолжи со следующего незавершённого этапа. Сохраняй чужие изменения, фиксируй проверки и обновляй план.

Если план устарел, сначала восстановите факты по коду и проверкам. Галочка в старом плане не доказывает, что код сейчас работает.

## Подключение к существующему проекту

1. Создайте рабочую ветку в существующем проекте, сохраните свои текущие изменения.
2. Скопируйте PLANS.md, docs/templates/PLAN.md и этот документ. Существующие одноимённые файлы объединяйте вручную.
3. Добавьте подходящие правила из AGENTS.md в существующий AGENTS.md; не заменяйте инструкции проекта. README существующего приложения сохраните.
4. Запустите Codex в корне существующего проекта и попросите исследовать стек, команды и проверки, затем сформировать спецификацию и план под конкретную задачу. Проверьте diff перед commit.

Не переносите чужие docs/SPEC.md и планы завершённых проектов как требования своего продукта. Не копируйте .git, секреты, зависимости и сборочные артефакты.

## Практический пример

> Хочу сервис учёта личных расходов: ручной ввод, категории, месячный отчёт. Это пример моего нового продукта. Сначала выясни существенные ограничения и выбери обоснованный стек. Сохрани спецификацию и план по правилам репозитория, затем реализуй минимальный рабочий сценарий и проверь его.

Это пример запроса, а не выбранный продукт шаблона.

## Перед передачей результата

Попросите Codex сопоставить AC-ID с тестами и сценариями, проверить diff и перечислить незапущенные проверки. Просмотрите изменения и результаты сами. Команды commit/push, PR и публикации выполняйте с нужными доступами и в рамках явно заданной задачи.
