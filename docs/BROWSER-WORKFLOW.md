# paiplan — стартовый набор для Codex в браузере

Набор нужен, чтобы описывать новую идею обычными словами, а Codex сам уточнял требования, составлял план, выполнял этапы и сохранял состояние в Git. Это предложенная адаптация подхода автора видео, а не дословный конспект или официальная конфигурация OpenAI.

## Один раз установить
1. Распаковать архив.
2. Добавить содержимое папки paiplan-starter в корень paiplan: AGENTS.md, PLANS.md, docs/ и, если нужны, файлы инструкции. Если в репозитории уже есть такие файлы, объединить инструкции; не перезаписывать существующее приложение или README.
3. Сохранить изменения в ветке, с которой начинаются следующие задачи Codex. Если изменения передаются через PR, после проверки включить их в эту ветку. Файл только в архиве или в непринятом PR не станет инструкцией основной ветки.
4. Открыть новую задачу Codex с этой веткой и дать короткое описание проекта.

AGENTS.md — постоянные правила. PLANS.md — процесс работы. docs/templates/PLAN.md — заготовка отдельного плана. docs/SPEC.md и docs/plans/<задача>.md появятся при работе над конкретным проектом. PLANS.md и шаблон не обладают специальной силой: их использование предписано в AGENTS.md.

## Новая идея
«Новый проект: <что хочу сделать>. Следуй AGENTS.md и PLANS.md. Уточни только существенные пробелы, подготовь спецификацию и план. Пока без реализации».

После просмотра: «Реализуй подготовленный план. Обновляй его по мере работы и выполняй проверки сам».

Если реализацию можно начинать сразу: «Новый проект: <идея>. Следуй AGENTS.md и PLANS.md. После необходимых уточнений составь план и реализуй первую версию».

## Продолжение
«Продолжи работу по docs/plans/<имя>.md. Сверь статус с кодом, восстанови контекст и выполни следующий незавершённый этап».

Проверь, что предыдущие изменения доступны выбранной задаче и ветке. Новый независимый запуск не следует считать продолжением несохранённого рабочего дерева.

## Новая функция
«Добавь <поведение>. Используй процесс репозитория, сохрани текущий стек и не расширяй объём задачи».

## Новые репозитории
Можно использовать paiplan как репозиторий-шаблон GitHub и создавать из него отдельный репозиторий для каждой независимой программы. Либо копировать AGENTS.md, PLANS.md и docs/templates/PLAN.md в новый репозиторий, объединяя существующие инструкции.

Подключение paiplan в Codex само по себе не переносит его правила в другие репозитории. Для каждого созданного репозитория нужно настроить соответствующий доступ в Codex. Готовность окружения проверяется фактической установкой зависимостей и запуском команд; setup script задаётся отдельно, когда известен стек. Не устанавливай в шаблоне Node, Python и базы данных «на всякий случай».

Если paiplan уже содержит приложение, используй эти файлы внутри него либо заведи отдельный чистый репозиторий-шаблон. Не объединяй независимые приложения в одну папку только ради общих инструкций.

## Как применены идеи видео
| Идея автора | Адаптация |
| --- | --- |
| Опрос перед работой | Только существенные неизвестные, без повторных вопросов |
| План и спецификация | Требования и состояние в файлах Git |
| Тесты до кода | TDD для логики и ошибок; подходящие проверки для остальных задач |
| Исправление до зелёных тестов | Исправлять причину, сохранять проверки, честно отмечать внешние блокировки |
| Оркестратор и worktree | Дополнительный режим при наличии инструментов и разрешения; основной процесс последовательный |

Ни AGENTS.md, ни просьба «запусти агентов» не создают отсутствующие инструменты и не позволяют гарантировать выбор разных моделей. Тесты подтверждают проверенные сценарии, а не отсутствие любых ошибок.
