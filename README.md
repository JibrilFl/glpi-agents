# GLPI Agent Installer

Приложение для установки GLPI Agent 1.16 на **Astra Linux** и **Linux Mint** по SSH. Введите IP-адрес, логин, пароль и URL GLPI: приложение определит систему, передаст нужные файлы и покажет результат. Проверены установка на устройства и запуск переносимой версии без Python.

**Скачать:** [последний релиз](https://github.com/JibrilFl/glpi-agents/releases/latest) · **Требования:** [docs/SPEC.md](docs/SPEC.md) · **История:** [CHANGELOG.md](CHANGELOG.md)

## Запуск без Python на Windows

Скачайте `GLPI-Agent-Installer.zip` из [Releases](https://github.com/JibrilFl/glpi-agents/releases), распакуйте его целиком и откройте `GLPI-Agent-Installer.exe` внутри папки. Переносить только `.exe` без папки `_internal` нельзя: там находятся Python-зависимости и файлы GLPI Agent. В архиве нет адресов вашей инфраструктуры и `.env`; URL GLPI вводится в окне. Если нужен адрес по умолчанию, создайте `.env` рядом с `.exe` по примеру `.env.example`:

```text
GLPI_SERVER=https://glpi.example.test/
```

Для повторной сборки на Windows с установленным Python запустите `./build.ps1` из корня репозитория. Сценарий создаст `dist/GLPI-Agent-Installer/` и ZIP-архив, проверит наличие исполняемого файла и отсутствие `.env`. [PyInstaller](https://pyinstaller.org/en/stable/) включает интерпретатор и зависимости в переносимую сборку.

## Запуск из исходников

На компьютере администратора нужен Python 3.10+ с Tkinter и доступ к устройству по SSH на порту 22. Из корня репозитория:

```powershell
python -m pip install -r requirements.txt
python app.py
```

Введите IP-адрес устройства, SSH-логин, пароль этой учётной записи и URL сервера GLPI. Учётная запись должна иметь право выполнять `sudo` с этим паролем; допустим также вход под `root`. Новый SSH-ключ показывается с отпечатком для подтверждения. Сверьте отпечаток с устройством перед продолжением.

Локальный `.env` можно создать по `.env.example`. `GLPI_SERVER` из него показывается в поле URL как редактируемая подсказка. Существующий локальный `.env` содержит прежний адрес GLPI, удалённый из скриптов. `.env` игнорируется Git. IP устройства и пароль приложение не сохраняет.

Установка передаёт все файлы выбранной папки во временный каталог на устройстве и запускает `install.sh`. Для Astra передаваемый `agent.cfg` собирается из шаблона: в строку `server` подставляется URL из окна. Скрипт Astra устанавливает зависимости, распаковывает архив, собирает агент, копирует конфигурацию и создаёт сервис systemd. Скрипт Mint устанавливает зависимости и запускает AppImage с `--install --server --runnow`. Для установки пакетов на устройстве нужен доступ к источникам `apt` и, для Astra, Perl-модулей. После выполнения временные файлы удаляются.

Для команды установки приложение открывает удалённый терминал, отключает эхо ввода и передаёт пароль только в ответ на запрос `sudo`. В журнале последовательно появляются строки «Открытие удалённого терминала», «Команда запущена. Ожидание sudo», «Права sudo подтверждены», затем вывод штатного `install.sh`. Запрос терминала или запуск команды ограничен 15 секундами. При долгом молчании уже запущенной команды приложение показывает сообщение об ожидании; после 3 минут без вывода на Mint или 15 минут на Astra останавливает команду с ошибкой. При повторном сбое сохраните строки от «Запуск установщика» до «Ошибка» без пароля.

## Проверки

```powershell
python -m unittest discover -s tests -v
python -m compileall -q app.py glpi_installer
git check-ignore .env
```

Автоматические тесты подменяют SSH-клиент. Пользователь проверил установку и переносимую сборку: ПК появились на сервере GLPI, приложение работает на целевом ПК. Итоги разработки записаны в [плане](docs/plans/initial.md).
