# paiplain — шаблон работы с Codex

Универсальный процесс для новых и существующих проектов: требования → план → реализация → проверки → сохранение состояния. Приложение, стек и зависимости выбираются под конкретный проект.

Основа — предоставленный START.md. Содержание видео не проверено: доступ к YouTube в среде был заблокирован.

## Один раз: подготовить шаблон

1. Опубликуйте эти файлы в репозитории `JibrilFl/paiplain` (commit и push).
2. На GitHub откройте **Settings → General → Template repository** и включите эту опцию. Нужны права администратора репозитория.
3. Для каждого продукта создавайте отдельный репозиторий. Не храните несколько независимых продуктов в этом шаблоне.

## Новый проект через GitHub

На странице шаблона нажмите **Use this template → Create a new repository**, задайте имя и видимость. Затем:

```bash
git clone https://github.com/YOUR_ACCOUNT/YOUR_PROJECT.git
cd YOUR_PROJECT
codex
```

Создание через шаблон даёт отдельную историю Git и не переносит последующие обновления шаблона автоматически. Не используйте Fork, если не нужна связь форка с исходным репозиторием.

## Новый проект обычным клонированием

Этот вариант сохраняет историю шаблона. Сначала создайте на GitHub новый пустой репозиторий без README и лицензии, затем:

```bash
git clone https://github.com/JibrilFl/paiplain.git my-project
cd my-project
git remote rename origin template
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_PROJECT.git
git push -u origin HEAD
codex
```

Замените примеры адресов своими. `origin` теперь указывает на новый проект; `template` остаётся источником обновлений. Проверьте `git remote -v` перед push. Не объединяйте обновления шаблона вслепую: правила и документы могли измениться под ваш продукт.

## Начать работу

Установите актуальный Codex CLI по официальной инструкции: https://developers.openai.com/codex/cli/ . Если Node.js уже соответствует требованиям CLI:

```bash
npm install -g @openai/codex
codex --version
```

Запускайте `codex` из корня проекта и пройдите авторизацию предлагаемым CLI способом. Установка CLI и авторизация выполняются на вашей машине; в этой среде они не проверялись. Не записывайте токены в репозиторий.

Первый запрос:

> Прочитай AGENTS.md и PLANS.md. Хочу создать [описание продукта и пользователей]. Изучи репозиторий, уточни только блокирующие вопросы, запиши требования в docs/SPEC.md и план в docs/plans/initial.md. Затем реализуй первый согласованный по требованиям этап, проверь результат и обнови план.

Подробнее: [работа и продолжение в CLI](docs/CODEX-WORKFLOW.md). Шаблон задаёт инструкции агенту; сам по себе он не запускает команды и не обеспечивает автоматические проверки политик.

Ранее опубликованная инструкция сохранена: [работа в браузере](docs/BROWSER-WORKFLOW.md).
